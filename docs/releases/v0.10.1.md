# Universal Research MCP 0.10.1

This release fixes a correctness defect in the local SentenceTransformer
embedding backend. Affected versions produced semantic vectors from randomly
initialized weights instead of the pinned checkpoint, so semantic, hybrid and
adaptive retrieval returned noise while reporting success.

## Affected scope

Read this section before upgrading; the defect is of the kind that returns
confident wrong answers rather than failing.

- **Affected:** any release up to and including 0.10.0 that used the
  `local_sentence_transformer` semantic backend through
  `universal-research semantic build`, `research_semantic_*`, or any
  semantic/hybrid/adaptive query path.
- **Affected retrieval modes:** semantic, hybrid and adaptive. Their ranking was
  effectively arbitrary.
- **Not affected:** lexical retrieval, the `signed_hashing_v1` deterministic demo
  backend, the canonical JSONL ledger, source registration, evidence fetch,
  SHA-256 verification and every claim gate. No canonical record was altered,
  and nothing needs to be re-ingested.
- **Not affected:** the standalone `tools/build_research_semantic_index.py`
  builder, which already reloaded the checkpoint after construction and
  validated the encoder against its published model-card scores.

Because the derived index is rebuildable from the canonical ledger, recovery is
a reindex; no research data was lost.

### Why it was not visible

A process that reinitializes weights at load time is still deterministic within
that process. Repeating a query in one session returned identical vectors, index
fingerprints matched, `research_index_status` reported `integrity: ok` and
`status: current`, and the Transformers load report listed no missing keys — it
reports on loading, which did succeed, while the overwrite happened afterwards.
Only comparing against the checkpoint itself, or across two processes, exposed
the defect.

## Fixes

- Weights installed from the checkpoint are retained through Transformers 5's
  finalization pass. Older pinned remote-code architectures initialize weights
  by mutating tensors in place, which Transformers' own guard cannot intercept;
  those modules were overwriting the whole checkpoint. Parameters genuinely
  absent from the checkpoint are still initialized normally.
- The loaded backbone is compared against the snapshot's `.safetensors` tensors
  before first use. A mismatch, an unverifiable parameter, or a snapshot with no
  readable checkpoint now raises instead of embedding. This fails closed even if
  a future runtime breaks loading in a different way.
- `research_index_status` binds its semantic report to the configured embedding
  identity, so an index written by a different or superseded embedder is
  reported `stale` rather than `current`.
- Embedding identity carries a loader generation, which is part of the index
  key. Indexes from affected releases are detected and rebuilt automatically
  instead of being silently reused.

The separate GTE rotary and position buffer restoration from 0.10.0 is retained;
it addressed non-checkpoint runtime buffers and did not cover this defect.

## Reindexing

Every semantic index built by an affected release is invalid and must be
rebuilt. The loader generation makes this automatic: the existing index is
reported `stale`, and the next build replaces it.

```bash
universal-research semantic status --root /path/to/project
```

```bash
universal-research semantic build --root /path/to/project
```

Confirm the rebuild, which must report the configured local backend and a
`current` index:

```bash
universal-research semantic status --root /path/to/project
```

Notes:

- Rebuilding re-embeds the corpus and takes as long as the original build.
- Delete nothing by hand. The build stages a new database and promotes it
  atomically; a failed build leaves the previous index in place.
- Hosts with `auto_refresh` disabled still require this explicit build.
- If a rebuild now fails with `does not match its checkpoint`, the snapshot is
  genuinely unusable in this environment. Re-run the approved `semantic setup`
  flow rather than bypassing the check.
- Any conclusion that relied on semantic or hybrid ranking from an affected
  release should be re-checked after reindexing. Evidence citations remain valid,
  since fetch and verification were never affected.

## Upgrade

```bash
python -m pip install --upgrade "universal-research-mcp==0.10.1"
```

```bash
python -m pip install --upgrade "urmcp==0.10.1"
```

The Codex plugin and the Claude Desktop bundle ship no package code of their
own; both launch the installed wheel. The Codex plugin therefore picks the fix
up from the upgrade above. The Claude Desktop bundle pins the wheel it
installs, so replace it with the 0.10.1 `.mcpb` from the release assets rather
than keeping the installed extension. `scripts/build_claude_desktop_bundle.py`
packs it and refuses a bundle whose pin lags the release.
